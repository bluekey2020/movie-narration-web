## 1. 产品定位

### 1.1 一句话定位

> **专为电影解说创作者打造的一站式 AI 创作 Web 平台 —— 从选片到成片，一个浏览器标签页全搞定。**

### 1.2 与 Flova / narrator-ai 的差异化

```
Flova.ai                = AI 制片厂（通用视频创作，广度优先）
narrator-ai-cli         = AI 解说命令行（影视解说，深度优先，技术门槛高）
Movie Narration Web     = AI 解说工作台（影视解说，深度优先，零门槛 Web 体验）
```

| 维度 | Flova.ai | narrator-ai-cli | **Movie Narration Web（本方案）** |
|------|----------|-----------------|----------------------------------|
| 创作领域 | 通用视频 | 影视解说 | **影视解说专精** |
| 交互模式 | 对话 + 画布 | 命令行 / Agent Skill | **Web 工作台（对话 + 时间线 + 预览）** |
| 风格控制 | 通用 prompt | 12 种解说风格 + 风格学习 | **12 种风格 + 风格市场 + 自定义调参** |
| 配音系统 | ElevenLabs 单模型 | 63 角色 / 11 语言 / 停顿语法 | **63 角色 + 语音克隆 + 情绪标注** |
| 视频合成 | 模型生成画面 | 剪辑数据 + FFmpeg 合成 | **剪辑引擎 + 模型画面 + 素材拼接双模式** |
| 多平台适配 | 无 | 抖音/B站/快手参数 | **全平台 + 版本管理 + A/B 测试** |
| 素材管理 | 项目内 | 无 | **素材库 + 电影数据库 + 标签系统** |
| 协作 | 无 | 子 Key 配额 | **团队空间 + 权限 + 审核流** |
| 上手门槛 | 低 | 中高（需命令行） | **极低（Web 界面）** |

### 1.3 目标用户画像

| 用户类型 | 痛点 | 我们提供的价值 | 优先级 |
|----------|------|---------------|--------|
| **影视解说博主** | 日更需要大量文案+剪辑，工具碎片化 | 一条龙出片，风格模板一键套用 | 🔴 核心 |
| **MCN 内容团队** | 多账号矩阵运营，风格统一难，审核成本高 | 团队协作+风格锁定+审核流 | 🔴 核心 |
| **个人副业创作者** | 想做解说但不会剪辑，不会写文案 | 选片→AI 生成→人工微调→自动出片 | 🟠 重点 |
| **影视营销号** | 需要快速跟进热点影视，时效性要求高 | 热点电影预置模板，30 分钟出片 | 🟠 重点 |
| **出海内容团队** | 中文解说转多语言，人工翻译配音成本高 | 多语言配音 + 字幕自动翻译 | 🟡 拓展 |
| **影视教育/培训** | 需要做影片分析、拉片讲解 | 分镜拆解模式 + 深度分析模板 | 🟢 潜力 |

## 2. 市场机会分析

### 2.1 为什么是"电影解说"这个垂直领域？

```
短视频内容创作的现状：

  通用 AI 视频工具（Flova/Runway/Sora）
  └─ 覆盖面广，但每个垂直场景都不够深
      │
      ├── 电商带货 ← 有专门的工具链
      ├── 游戏录屏 ← 有专门的工具链
      ├── 影视解说 ← ❌ 没有专门的 AI 工具链
      ├── 知识科普 ← 通用工具勉强够用
      └── Vlog 创作 ← 剪映覆盖得很好

结论：影视解说是 AI 视频创作领域最大的"垂直空白地带"
```

| 指标 | 数据 |
|------|------|
| 抖音 #电影解说 话题播放量 | 超过 8,000 亿次 |

| 解说类 MCN 机构数 | 200+ |

## 3. 核心设计理念

### 3.1 四大设计原则

```
原则 1：创作者永远拥有最终控制权
  AI 生成 → 人工审阅 → 确认后合成，每一步都有"把关人"窗口
  借鉴 narrator-ai 的 Standard Path 人工介入设计

原则 2：风格可学习、可复用、可交易
  借鉴 Flova Skill 生态 + narrator-ai 风格学习两步法
  风格不只是模板，是包含了叙事节奏、配音情绪、BGM 选曲的完整"创作指纹"

原则 3：降低三大门槛，但不替代审美
  操作门槛 → 降到零（Web 界面，不需要命令行）
  技术门槛 → 降到零（AI 处理字幕/分镜/合成，不需要 FFmpeg 知识）
  设备门槛 → 降到零（云端处理，不需要 GPU/大内存）
  审美门槛 → 不替代，但提供参考（风格市场 + 爆款分析）

原则 4：本地素材安全 + 云端算力弹性
  借鉴 narrator-ai 的 Local-First 架构
  原片不上传（或加密分片上传），仅传输轻量载荷
```

### 3.2 产品的"三句话"测试

> - 一个新用户，从注册到第一条成片，应该在 **30 分钟** 内完成
> - 一个有经验的用户，制作一条解说视频，应该在 **15 分钟** 内完成
> - 一个 MCN 团队，管理 10 个账号的日更，应该能在 **2 小时** 内完成全流程

### 4.2 核心架构决策

| 决策 | 选择 | 理由 |
|------|------|------|
| Agent 编排引擎 | 自研工作流引擎 (Temporal) | 解说流程步骤多、有依赖关系、需要人工审批点、可中断可恢复 |
| 视频合成位置 | 云端 FFmpeg 集群 | Web 用户无法本地运行 FFmpeg，需要云端处理 |
| 原片处理策略 | 可选：本地处理 / 云端加密处理 | 兼顾安全性和便利性 |
| 文件存储 | S3 兼容对象存储 + CDN | 视频文件大，需要 CDN 加速下载 |
| 实时通信 | WebSocket | 任务进度推送、SSE 替代轮询 |
| 模型调用 | 统一路由 + 多供应商 fallback | 避免单一模型依赖，成本优化 |

### 4.3 本地-云端混合策略

```
┌─────────────────────────────────────────────────────┐
│                  方案 A：云端模式（推荐普通用户）        │
│                                                     │
│  用户上传原片 → 云端加密存储 → AI 处理 → 合成 → 导出   │
│  优点：零门槛，任何设备都能用                           │
│  缺点：上传大文件耗时                                  │
├─────────────────────────────────────────────────────┤
│                  方案 B：混合模式（推荐专业用户）        │
│                                                     │
│  本地提取字幕/关键帧 → 上传轻量载荷 → 云端 AI 处理      │
│  → 下载配音/字幕 → 本地 FFmpeg 合成                    │
│  优点：原片不上传，带宽友好，隐私安全                    │
│  缺点：需要安装本地 Companion 客户端                    │
└─────────────────────────────────────────────────────┘
```

### 5.2 核心功能详解

#### 5.2.1 智能选片

```
输入方式：
  • 搜索片名（实时搜索 + 智能补全）
  • 电影数据库浏览（按类型/年份/评分/热度筛选）
  • 热点追踪（实时抓取各平台热搜榜）
  • URL 导入（粘贴豆瓣/IMDb/TMDB 链接自动识别）
  • 本地上传（拖拽视频文件）

智能推荐逻辑：
  • 热门解说电影（各平台解说视频数量排序）
  • 潜力新片（上映 1 周内，解说竞争度低）
  • 经典常青树（长期稳定的解说流量）
  • 你的创作历史（根据过往偏好推荐）
```

#### 5.2.5 风格学习器

借鉴 narrator-ai 的两步法，但在 Web 端做了可视化增强：

```
Step 1：上传参考视频
  ├── 上传一条你觉得"写得特别好"的解说视频
  ├── 系统自动提取字幕 SRT
  └── （可选）标注你喜欢的段落和句式

Step 2：AI 风格提取
  ├── 分析：叙事节奏曲线（句子长度变化模式）
  ├── 分析：钩子密度（每 100 字多少个钩子点）
  ├── 分析：情绪起伏（从紧张到轻松的切换频率）
  ├── 分析：词汇偏好（高频词/句式/梗的使用模式）
  ├── 分析：BGM 切点模式（什么时候换音乐）
  └── 输出：可视化风格指纹雷达图

Step 3：风格应用
  ├── 选择新电影
  ├── 选择刚提取的风格
  ├── AI 按风格指纹生成文案
  └── 对比：原风格 vs 新文案的风格相似度评分
```

**风格雷达图**（可视化）：

```
        叙事节奏
           /\
          /  \
    词汇   │  │  钩子
    风格   │  │  密度
          \  /
           \/
        情绪起伏

  ── 你的参考风格
  ── 生成的文案风格
  （重叠度越高，风格迁移越成功）
```

### 8.3 风格学习器（核心差异化功能）

```
输入：
  • 参考解说视频（抖音/B站/快手链接，或直接上传）
  • 可选：标注"我喜欢这段"的段落

AI 提取过程（后端）：
  ┌─────────────────────────────────────────────┐
  │ Step 1：字幕提取 + 标点分析                   │
  │ Step 2：句子切分 + 长度统计 → 节奏曲线        │
  │ Step 3：钩子识别（设问/反转/悬念/数据冲击）     │
  │ Step 4：情绪分类（每句 → 情绪标签+强度）        │
  │ Step 5：BGM 切点检测（音频能量变化点）          │
  │ Step 6：高频词/句式提取                       │
  │ Step 7：综合 → 风格指纹（JSON + 雷达图）        │
  └─────────────────────────────────────────────┘

输出：
  • 风格指纹 JSON（可被生成引擎直接调用）
  • 可视化雷达图（用户可直观理解风格特征）
  • 相似风格推荐（系统内已有的相近风格）
  • 风格命名 + 描述（用户可自定义）

应用：
  • 选择任何电影 → 选择该风格 → 生成风格化文案
```

## 14. 风险评估与应对

### 14.1 核心风险矩阵

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| narrator-ai API 不稳定/涨价 | 中 | 高 | 自研风格学习和 TTS 模块作为 fallback；多供应商并行 |
| 视频生成模型画质不足 | 高 | 中 | 优先素材剪辑模式；AI 生成作为辅助；跟随模型迭代 |
| 竞品跟进（Flova/剪映做解说专版） | 中 | 高 | 快速建立风格生态壁垒；积累独家风格数据 |
| 版权合规风险（素材使用） | 中 | 高 | 本地优先架构减少传输；法律顾问审核；DMCA 响应机制 |
| 用户增长不及预期 | 中 | 中 | 与 MCN 机构深度绑定；KOL 推广；免费版降低获客成本 |
| 视频合成成本过高 | 中 | 中 | 优化 FFmpeg 集群效率；引入本地合成客户端选项 |

### 14.2 竞争优势衰减应对

```
Flova 的教训：
  "底层模型依赖是最大的风险——Flova 的画质天花板受限于 Seedance/Sora"

我们的应对：
  1. 我们的核心竞争力不在"画质"，而在"解说风格引擎"和"影视创作工作流"
  2. 底层模型越强，我们的产品越好用（不是零和博弈）
  3. 风格数据是护城河——积累越多风格-电影-平台的匹配数据，
     我们的风格推荐和文案质量就越好，这是模型厂商无法轻易复制的
```
